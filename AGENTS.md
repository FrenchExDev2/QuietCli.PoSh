# QuietCli2 monorepo

## Script-first automation

- Any automatable operation on this repository is done through a script under `scripts/` (discover what already exists with `Get-ChildItem scripts -Recurse`, or browse the [scripts documentation index](docs/scripts/README.md)), never an ad hoc inline command improvised for one occasion. Extend an existing script before writing a new one that overlaps it.
- At the start of every discussion that touches this repository, actively look for the opportunity to turn a manual or ad hoc sequence into a new or extended script under `scripts/`. A one-off command typed into a shell is a missed script, not a shortcut. A new or changed script must ship with its own doc under `docs/scripts/`, mirroring its subdirectory - see [Every script has a doc](docs/README-scripts-have-docs.md); the gate is `scripts/Sync-ScriptsReadme.ps1`.

## Automation requirements as code

- RAC-BUILD-001: local and GitHub CI use `Build-Workspace.ps1` to compile `Quietly.slnx` once, then prepare portable distributions with `dotnet publish --no-build`. `Get-QuietWorkspaceBuildProjects` derives project/framework/output values from inert `PrivateData.QuietCli.BuildProjects` declarations; build and binary identity consume the same function. New consumers declare their compiled outputs and join the solution without editing launcher lists. Pure PowerShell consumers need no compiled declaration. Preserve targeted engine RID/ReadyToRun publications, integrity receipts, warning-as-error policy, container inputs, fail-fast behavior and no-effect WhatIf. Companion properties, malformed declarations and mutations must verify the contract; local evidence never substitutes for the hosted matrix.
- RAC-PS-003: directly under `scripts/`, keep PowerShell entry points and existing function-only helpers as `.ps1`; every dependent automation `.psm1` belongs under `scripts/lib/`, including future nested libraries. Mirror each library at `docs/scripts/lib/<name>.md` and each entry point at `docs/scripts/<name>.md`, indexed by `Sync-ScriptsReadme.ps1`. The ScriptShouldProcess gate rejects misplaced modules even if a legacy entry or exception would otherwise admit them. Keep library exports and dependencies explicit, import silently without business effects, and review cohesive libraries as candidates for extraction into independent companion modules as their use grows. A declarative initializer may set strict mode, declare exports and import a sibling library; that classification never waives runtime preview tests or qualifies arbitrary executable initialization.
- RAC-PR-001: after explicitly authorized pushes of `feature/*` or `fix/*` branches to GitHub projects, add a PR comment summarizing the pushed checkpoint, changes and actual validation. Read the existing PR context first; use GitHub CLI and a UTF-8 Markdown body file. `Push-Workspace.ps1` automates this for the selected GitHub remote and one existing open PR; supply `-PrCommentBodyFile` for a reviewed detailed update, otherwise it lists current PR commits without claiming qualification. Never create a PR implicitly, duplicate the same checkpoint comment, edit another comment, or run the full companion suite merely to push. WhatIf sends neither push nor comment. Report comment failures separately from a completed push.
- RAC-ENV-001: local/GitHub configuration resolution belongs in a shared function: explicit invocation options override the selected checkout's `.env`, and programmatic discovery runs only when the key is absent. `QUIET_CONTAINER_RUNTIME` accepts exactly `podman` or `docker`; invalid, empty or duplicate assignments fail explicitly. Unconfigured workstations discover Podman before Docker on Windows and Linux. `Initialize-CiEnvironment.ps1 -Target Local|GitHub` deterministically writes the preset through the shared dotenv editor with standard WhatIf/Confirm. GitHub execution jobs initialize their checkout's Docker preset before running scripts. Preserve unrelated keys, never evaluate dotenv contents, never print unrelated values, and never stage or publish a private `.env` wholesale. New environment-dependent automation must use the shared resolution/editor contract and ship local/GitHub precedence, preview and malformed-input tests.
- RAC-WF-001: every change to `.github/workflows/*.*` requires reviewing its matching `docs/ci/github/script-<basename>.md` and updating the source SHA-256 receipt. `scripts/Sync-GitHubWorkflowsReadme.ps1 -Apply` regenerates the job/dependency Mermaid blocks and the [workflow entry point](docs/ci/github/README.md); it never authors missing docs or refreshes reviewed receipts. `scripts/Test-GitHubWorkflowDocs.ps1` blocks missing/stale contracts and graph/index drift.
- RAC-PS-001: new executable PowerShell scripts support standard `-WhatIf`/`-Confirm` wherever possible, using `CmdletBinding(SupportsShouldProcess)` and `$PSCmdlet.ShouldProcess` before effects. Add runtime no-write preview tests. Function-only libraries delegate effects; purely read-only entry points require justified hash-bound exceptions. `scripts/Test-ScriptShouldProcess.ps1` enforces the new-script policy; the frozen legacy inventory remains explicitly unqualified and must not be extended to waive new scripts.
- RAC-RES-001: resource changes and changes to their source consumers require reviewing [README-resources.md](README-resources.md) and regenerating `docs/resources/README.md` with `scripts/Sync-ResourcesReadme.ps1 -Apply`. The shared registry and Commit-Workspace run `Test-Resources.ps1`; `-NoResourcesCheck` explicitly reports its omission. Preparation belongs in the resource consumer/helper, not in a required preceding workflow step.
- RAC-PS-002: do not add objective comment headers or automatic objective announcements to `scripts/**/*.ps1`. Describe purpose in English comment-based help. `Sync-ScriptContracts.ps1` removes obsolete headers/announcements and generates the complete preview review and mirrored execution contracts; `Test-ScriptContracts.ps1` checks them. Keep purposeful progress and terminal summaries, including failures/crashes/timeouts, without an objective tag. Long runs stream their own existing reports; never automatically capture native business output or collect product events for logging. `-NoScriptContractsCheck` explicitly reports omission. English objective comments on agent tool commands remain separate from script source/output.
- Report monitors are read-only: stream bounded tails of the run's existing diagnostic files, distinguish observed bytes/lines from test counts, retain project identity and resize-aware framing, and close after a saved terminal summary. Agent commands must analyze their result and deliver a bounded summary, rather than dumping arbitrary output.
- `scripts/Invoke-WorkspaceChecks.ps1` is the shared ordered check registry for local validation, `Commit-Workspace.ps1` and `scripts-docs-check.yml`. Add future checks there. `-SkipCheck` reports explicit omissions; it never marks them successful. Commit compatibility switches include `-NoGitHubWorkflowDocsCheck` and `-NoScriptShouldProcessCheck`. `-NoSyncChecks` skips documentation checks but retains script safety. `-NoAll` checks the exported prepared index, including its policy and source lock, rather than unstaged fixes.
- See [the automation contract](docs/README-automation-contracts.md) for acceptance evidence and static-check limitations.

- Local native C qualification includes compilation, unit/process properties, coverage-guided fuzzing and mutation. GitHub CI does not run these TTY campaigns. ## Property testing, fuzzing and mutation testing

- Property-based testing, fuzzing and mutation testing are mandatory parts of the test strategy for every implementation language, including PowerShell, C#, C and future languages. Consider all three when writing or changing tests; ordinary example tests alone do not satisfy this strategy. Reuse and extend existing companion test projects, generators, corpora, mutation catalogues and runners.

- Execute the relevant campaigns when necessary: new or changed behavior, parsers or serializers, protocols or input validation, state/lifecycle/concurrency logic, a bug exposing a missing invariant, changes to assertions/generators/corpora/mutation tooling, or a dependency/runtime change affecting those guarantees. Run a deterministic regression for each discovered defect and retain its minimized reproducer or seed.
- Scope runs to the affected component and its dependent behavior. Do not rerun every campaign after every edit, read-only operation or documentation-only change. Reuse successful evidence only while its source, tests, dependencies, runtime and configuration remain applicable; explain the selected scope and why existing evidence is sufficient when no new campaign is needed.

Missing tooling or an unexecuted required campaign is an explicit qualification gap, never an implicit pass or an automatic waiver.
- Bound campaign duration and resources, retain seeds/corpora and source identity, and report property/fuzz executions and mutation outcomes separately. Investigate surviving mutants; distinguish equivalent mutants with evidence from missing assertions, invalid mutants, crashes, timeouts and infrastructure failures. Preserve failures and respect the repository's visible-monitor and artifact rules.

## Test selection and fail-fast

- Local commits and pushes on work branches (including feature/* and fix/*) do not require or automatically start companion suites. Keep the shared source/documentation checks and source-lock validation. Ask before launching a full local companion or mutation campaign unless the user explicitly requested that run. A local checkpoint is not qualification evidence.
- GitHub workflows own the required PR/develop/release qualification. Full, unfiltered evidence is required for the scope claimed by those workflows and publication gates; partial, stopped or cancelled runs never qualify a delivery. Remote branch protection remains a separate repository configuration.
- `Invoke-WorkspaceCi.ps1 -StopOnFirstFailure` is an opt-in development switch: the monitor stops at the first failing case so it can be fixed immediately. The report states "stopped at case N of M" and is flagged incomplete.
- `Invoke-WorkspaceCi.ps1 -Case <wildcard>` runs only the matching cases. The report is flagged partial. The two options can be combined.
- Both options apply to the owning Core, Git or Vagrant runner (the worker exposes QUIETCLI_TEST_CASE / QUIETCLI_TEST_STOP_ON_FIRST_FAILURE). Each companion declares its own .psm1 metadata and manifest TestCatalogue/TestExecution policy; shared infrastructure discovers/validates it without importing product code. Summaries carry Partial, Incomplete, StoppedAt and Skipped; partial/stopped runs never qualify.
