# Sync-Credits.ps1

## Purpose

Keeps the repository's root `CREDITS.md` file in sync with every business module's own
`LICENSE_CREDITS.md`. The business problem: this is a multi-module monorepo where each shipped module
(Core, Git, Vagrant — "never a .Tests companion" per the script's own `.DESCRIPTION`) bundles a
third-party native dependency under its own license; the repository needs one navigable, generated
root document instead of hand-maintained duplication that would drift. It is invoked both by a human
running `./scripts/Sync-Credits.ps1` (optionally `-Apply`) and by CI: the referenced
`.github/workflows/sync-credits-check.yml` and `sync-credits-apply.yml` workflows exist specifically to
run this script in check mode (gate) and apply mode respectively. `docs/README-credits-and-syncing.md`
documents the human-facing workflow around it, and `CREDITS.md` itself states it is generated by this
script.

## Usage

```
[CmdletBinding(SupportsShouldProcess)]
param(
    [string]$WorkspaceRoot = (Split-Path $PSScriptRoot -Parent),
    [string]$CreditsPath = (Join-Path (Split-Path $PSScriptRoot -Parent) 'CREDITS.md'),
    [switch]$Apply
)
```

- `WorkspaceRoot` (string, optional) — monorepo root containing the `FrenchExDev2.QuietCli.*.PoSh`
  project directories. Defaults to the script's own parent directory.
- `CreditsPath` (string, optional) — destination for the generated file. Defaults to
  `CREDITS.md` at the workspace root.
- `Apply` (switch, optional, default `$false`) — without it, the script only reports compliance and
  writes nothing. With it, it writes the regenerated file (honoring `-WhatIf`/`-Confirm` via
  `SupportsShouldProcess`).

Examples (from the script's own doc comment):

```powershell
./scripts/Sync-Credits.ps1                  # report only
./scripts/Sync-Credits.ps1 -Apply -WhatIf   # preview the write
./scripts/Sync-Credits.ps1 -Apply           # write CREDITS.md
```

## Dependencies

- Dot-sources `WorkspaceProjects.ps1` (line 40) for `Get-QuietWorkspaceProjects`.
- No external process is shelled out to; pure PowerShell file I/O and regex.
- Filesystem assumptions: every non-test project returned by `Get-QuietWorkspaceProjects` must contain
  a `LICENSE_CREDITS.md` with at least one `##`-level Markdown heading (line 88-89); any missing file
  or missing heading throws and aborts the whole run (lines 83-96), i.e. one incomplete module blocks
  credits generation for all modules.

## Side effects

- In report mode (default): no filesystem writes; only reads module `LICENSE_CREDITS.md` files and the
  existing `CREDITS.md` (if present) to compute a `State` (`Missing`/`Stale`/`UpToDate`).
- With `-Apply` (and `ShouldProcess` approval): overwrites `CreditsPath` (`CREDITS.md` by default) with
  UTF-8, no-BOM content (line 124), replacing it entirely with the recomputed text.
- Throws (and thus fails the calling CI job) when the final state is not `UpToDate`/`...(Applied)`
  (lines 129-131) — this is the intended check-mode gate behavior.

## Findings

- No bugs found in the core comparison/generation logic after reading it closely: the TOC-anchor
  slugger (lines 61-73), the begin/end marker wrapping (lines 46-59), and the trim-based
  missing/stale/up-to-date comparison (line 119) are all straightforward and match the documented
  behavior.
- CONVENTION: Every file read/write in this script uses synchronous `Get-Content -Raw` /
  `[System.IO.File]::WriteAllText` (lines 87, 118, 124) rather than the async
  `.GetAwaiter().GetResult()` pattern AGENTS.md mandates even for synchronous PowerShell. Given the
  file sizes involved (small Markdown files) this has no practical performance impact, but it is a
  literal convention violation and inconsistent with sibling scripts such as `Sync-SkillDocument.ps1`
  and `AgentDocuments.ps1`, which do use `ReadAllTextAsync`/`WriteAllTextAsync` with
  `.GetAwaiter().GetResult()`.
- DESIGN: UTF-8/LF discipline is enforced for the *output* (`[System.Text.UTF8Encoding]::new($false)`,
  line 124) but the *input* reads (`Get-Content -Raw -Encoding UTF8`, line 87) do not verify the source
  `LICENSE_CREDITS.md` files are LF-only or reject `\r`, unlike `Sync-SkillDocument.ps1`'s explicit
  `if($agents.Contains("`r")){throw ...}` guard. A module's `LICENSE_CREDITS.md` with CRLF line endings
  would silently propagate CRLF fragments into the generated `CREDITS.md` blocks, which is exactly the
  kind of encoding drift the repository's own "Text encoding and line endings" convention is meant to
  prevent.
- Testability gap: no Pester test file under `FrenchExDev2.QuietCli.Core.Tests.PoSh` or the other
  `*.Tests.PoSh` projects references `Sync-Credits.ps1`, `Get-ModuleCreditsBlock`, or
  `Get-MarkdownHeadingAnchor` (searched `*.Tests.ps1` for the term — no hits). The only verification is
  the CI workflow running the script itself against real repository content, which is an integration
  check, not a unit/property test of the anchor-slugging or staleness-comparison logic in isolation
  (e.g. no test covers a heading with non-Latin characters, duplicate headings producing colliding
  anchors, or a `LICENSE_CREDITS.md` missing its heading entirely beyond the one `throw`).
- No security concern: the script only reads module-local files it already trusts (same monorepo) and
  writes one well-known path; no secrets, no network, no untrusted input.

## Verdict

Fit for purpose for its narrow job (keep CREDITS.md in sync, gate on staleness in CI); the highest
priority fix is adding an explicit CRLF/UTF-8 rejection on the `LICENSE_CREDITS.md` inputs (mirroring
`Sync-SkillDocument.ps1`'s guard) so a module with inconsistent line endings cannot silently corrupt the
generated root document.
